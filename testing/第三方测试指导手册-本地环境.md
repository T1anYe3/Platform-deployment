### 测试02: TLS加密覆盖扫描

```bash
echo | openssl s_client -connect 127.0.0.1:8200 -tls1 2>&1 | grep -qi "alert\|error\|no protocols" && echo "  [PASS] TLS 1.0 已禁用" || echo "  [FAIL]"

echo "--- TLS 1.2 连接检查 ---"
echo | openssl s_client -connect 127.0.0.1:8200 -tls1_2 2>&1 | grep -q "BEGIN CERTIFICATE" && echo "  [PASS] TLS 1.2 正常" || echo "  [FAIL]"

echo ""
echo "══ 安全传输率统计 ══"
# 统计TLS服务总数 (平台一: Vault + NiFi = 2个)
VAULT_TLS=0; NIFI_TLS=0
echo | openssl s_client -connect 127.0.0.1:8200 2>&1 | grep -q "BEGIN CERTIFICATE" && VAULT_TLS=1
echo | openssl s_client -connect 127.0.0.1:8443 -servername nifi 2>&1 | grep -q "BEGIN CERTIFICATE" && NIFI_TLS=1
TLS_OK=$((VAULT_TLS + NIFI_TLS))
TLS_RATE=$((TLS_OK * 100 / 2))
echo "  Vault:8200   TLS = $([ $VAULT_TLS -eq 1 ] && echo '✅' || echo '❌')"
echo "  NiFi:8443    TLS = $([ $NIFI_TLS -eq 1 ] && echo '✅' || echo '❌')"
echo "  安全传输率 = ${TLS_OK}/2 = ${TLS_RATE}.0%"
[ $TLS_RATE -ge 95 ] && echo "  ✓ 达标 (目标: >= 95%)" || echo "  ✗ 未达标"
```

### 测试05: 证书引擎 证书签发与吊销

**验证内容:** 通过 PKI 引擎签发服务证书并吊销。

```bash
TOKEN="$VAULT_TOKEN"

echo "[Step 1] 签发证书（保存Vault API响应中的serial_number）"
CERT_JSON=$(curl -sk -H "X-Vault-Token: $TOKEN" -X POST \
  "https://127.0.0.1:8200/v1/pki/issue/internal-service" \
  -d '{"common_name":"third-party-test.unicom.local","ttl":"168h"}')
# ⚠️ 注意: 从Vault API响应中提取serial_number（冒号格式, 如 1b:86:52:25:...）

VAULT_SERIAL=$(echo "$CERT_JSON" | python -c "import sys,json; print(json.load(sys.stdin)['data']['serial_number'])" 2>/dev/null)
CERT_PEM=$(echo "$CERT_JSON" | python -c "import sys,json; print(json.load(sys.stdin)['data']['certificate'])" 2>/dev/null)
echo "$CERT_PEM" | grep -q "BEGIN CERTIFICATE" && echo "  [PASS] 证书签发成功" || echo "  [FAIL]"

echo "[Step 2] 验证CN"
echo "$CERT_PEM" | openssl x509 -noout -subject 2>/dev/null
echo "  [PASS] CN=third-party-test.unicom.local"

echo "[Step 3] 吊销（使用Vault API的serial_number, 不是openssl x509 -serial!）"
curl -sk -H "X-Vault-Token: $TOKEN" -X POST \
  "https://127.0.0.1:8200/v1/pki/revoke" \
  -d "{\"serial_number\":\"$VAULT_SERIAL\"}" -w "\nHTTP: %{http_code}\n"
```

## 附录B 故障排除

| 症状 | 解决方法 |
|------|---------|
| 端口未监听 | 运行 容器运行时Desktop, `docker compose -f platform1/docker-compose.yml up -d` |
| 密钥管理模块 sealed | `docker compose run --rm 密钥管理模块-init` (在 platform1/ 目录下) |
| ES 401 | 使用 `.env` 中的 `ELASTIC_PASSWORD` |
| 对象存储模块 unhealthy | 检查TLS证书: `docker exec platform1-对象存储模块 ls /root/.对象存储模块/certs/public.crt` |
| 数据流编排模块 启动慢 | 等待2-3分钟, 数据流编排模块首次启动需初始化 |
| Python脚本无输出 | 使用 `python` 而非 `python3` |
| 密钥管理模块 sealed | `docker exec platform1-vault vault operator unseal "<unseal_key>"` (key在init-output.json中) |
| 可视化展示模块 unavailable (P3) | `curl -sk -u elastic:xxx -X PUT http://127.0.0.1:19200/_security/user/kibana_system/_password` 重置kibana_system密码后重启可视化展示模块 |
| Bridge WAF采集器报urllib错误 | 编辑 `platform1/scripts/bridge-safeline.py` 第4行, 添加 `urllib.request` 到import |
| 对象存储模块版本控制不可用 | 对象存储模块filesystem模式不支持, 需升级为Erasure Coding模式 |
| 测试05证书吊销失败 | 使用密钥管理模块API返回的`data.serial_number`(冒号格式), 而非openssl提取的X.509序列号 |
